# 数据字典

## 工单流水 `orders.jsonl`

UTF-8，支持文件头 BOM。每个物理行一个对象，行号从 1 开始。

| 字段 | 类型 | 规则 |
|---|---|---|
| `id` | 字符串 | 工单业务键，保留前导零 |
| `show`、`title` | 字符串 | 演出及工序标题 |
| `stage`、`role` | 字符串 | 工位及技师工种，必须有日历定义 |
| `duration`、`reset` | 整数分钟 | 作业时长、作业结束后工位清场时间，清场默认为 0 |
| `release`、`deadline` | 整数分钟 | 当地作业日以内的放行和截止，放行默认 0 |
| `priority` | 整数 | 数字越小越先编排，默认 5 |
| `needs` | 字符串数组 | 直接前置工单，清理重复并稳定排序 |

## 剧场日历 `calendar.json`

- `date` 是剧场当地作业日。`venue`、`stages` 与 `technicians` 中的 `windows` 采用自当天零点起的分钟数，允许范围 0 至 2880。`[开始, 结束)` 的结束端可与后续工序衔接。剧场允许的营业段决定开工限制，1440 起归入次日。
- `stages` 用工位名索引窗口。`technicians` 用技师号索引姓名 `name`、工种 `role` 和 `windows`。交集是实际可开工窗口，午间闭场和晚间闭场都切开区间。
- `holds` 包含预约号 `id`、资源类型 `type`、资源键 `resource`、起止 `start` 与 `end`。同一资源的重叠预约都进入占用判断。无效预约中的已知资源按待核实处理，保留来源序号。

## 输出和证据

输入物理行在采信、重传、空行或源隔离中唯一归类。每条采信工单在 `scheduled`、`pending` 或 `isolated` 中唯一归类。`line` 是工单行号，`source_index` 是日历预约项位置，`related` 保存环成员、前置工单、预约号或资源键。超时按作业完工减截止计算。清场时间仅占用舞台。原有预约重叠单独报告。归档保存完整输入与计算结果，摘要按稳定 JSON 和规则版本计算。
